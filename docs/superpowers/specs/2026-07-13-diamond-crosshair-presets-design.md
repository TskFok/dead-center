# 四种菱形旗标准星设计

日期：2026-07-13

## 背景与目标

用户提供 `/Users/ushopal/Downloads/center.jpg`，要求把图片四个象限中的四种准星加入 Dead Center 的可选方案。现有三种方案必须保留，因此完成后共有七种可选准星。

参考图只决定造型，不固定红、绿、黄、青配色。四种新方案继续使用现有的主色、中心标记色、透明度、整体尺寸、线条粗细和中心间距设置。

## 范围

本次包含：

- 新增四个前后端一致的准星枚举值。
- 用可缩放的矢量图形渲染四向旗形臂和中心菱形。
- 在设置页加入四个方案选项，并让中心间距控件支持这些方案。
- 把“中心点颜色”文案改为适用于圆点和菱形的“中心标记颜色”。
- 更新自动化测试和 README 中的方案数量、名称与参数文案。

本次不包含：

- 删除或改变现有三种准星的外观和默认值。
- 引入新的持久化字段或提升配置版本。
- 固化参考图配色、加入逐方案独立配色，或把参考 JPEG 打包进应用。
- 改造设置页整体布局或交互模式。

## 方案比较

### 方案一：React 结构加 CSS 矢量图形（采用）

用四个臂元素和一个中心菱形元素组成新方案，以 CSS 修饰类控制长度、粗细、尖端方向、空心或实心状态。

优点是可直接复用现有 CSS 变量、任意缩放仍清晰、无需新增运行时依赖，并且能通过 DOM 结构测试稳定验证。代价是需要维护一组针对四种变体的 CSS 规则。

### 方案二：内联 SVG

SVG 也能精确表达菱形和旗形，但需要额外处理 `viewBox`、描边缩放与现有像素参数之间的换算。它会让当前以 DOM/CSS 为主的轻量组件出现第二套渲染模型。

### 方案三：裁切位图或遮罩素材

直接使用参考图最省造型代码，但 JPEG 带有背景、分隔线和标题遮挡，无法得到完整透明素材；位图换色和缩放效果也不符合现有可调准星的需求。

## 方案标识与显示名称

四个新增的稳定标识和设置页名称为：

| TypeScript 标识 | Rust 枚举 | 中文名称 | 参考象限 |
|---|---|---|---|
| `fine-diamond` | `FineDiamond` | 细旗空心菱形 | 左上 |
| `inward-diamond` | `InwardDiamond` | 内向旗空心菱形 | 右上 |
| `long-diamond` | `LongDiamond` | 长旗空心菱形 | 左下 |
| `solid-diamond` | `SolidDiamond` | 长旗实心菱形 | 右下 |

Rust 继续使用 `#[serde(rename_all = "kebab-case")]`，因此序列化字符串与 TypeScript 标识完全一致。

## 渲染设计

`Crosshair` 继续作为设置页预览与透明覆盖层共用的唯一渲染组件。

四种新方案共享以下结构：

- 根元素保留 `crosshair--<preset>` 和 `data-preset`。
- 四个 `.crosshair__flag` 元素分别表示上、右、下、左四条臂。
- 一个 `.crosshair__diamond` 元素表示中心标记。
- 主色 `--crosshair-primary` 用于四条臂；强调色 `--crosshair-accent` 用于中心菱形。

CSS 通过定位和 `clip-path: polygon(...)` 生成旗形尖端，通过边框或背景切换空心、实心菱形。四个变体只调整比例与端点方向：

- 细旗空心菱形：最细、最短，臂的尖端朝外，中心为空心细描边。
- 内向旗空心菱形：略粗、略长，臂的尖端朝中心，中心为空心细描边。
- 长旗空心菱形：长臂、较粗，臂的外端为尖角，中心为空心较粗描边。
- 长旗实心菱形：最长、最粗，臂的内端为尖角，中心为实心。

整体尺寸控制根元素宽高，透明度控制根元素透明度，线条粗细同时影响臂厚度和菱形描边。中心间距控制臂与中心标记之间的距离；CSS 保留足以看清菱形的最小净空，避免间距为零时完全遮住中心。

参考图右下方案顶部出现的绿色段不作为固定双色设计处理；它随其他臂统一使用用户选择的主色。

现有圆点、圆环、同心标记和缺口十字使用原有结构及样式，避免视觉回归。

## 设置页设计

设置页 `PRESETS` 数组追加四项，保留现有按钮、`aria-pressed` 语义和单列布局。七项允许页面自然纵向滚动，不引入新的滚动容器或布局模式。

中心间距滑杆对 `classic-cross` 和四种菱形旗标方案启用，对两个圆环类方案禁用。第二个颜色控件的可见文案和可访问名称统一改为“中心标记颜色”。

每个新增按钮使用简短提示说明差异：低干扰、朝心指引、远距清晰和强中心锚点。实际预览仍由上方实时舞台显示，按钮内部不重复嵌入微型准星。

## 数据流与兼容性

用户选择新方案后，设置页按现有 100 毫秒防抖调用 `updateVisual`。Tauri 侧把 kebab-case 标识反序列化为对应 Rust 枚举并按现有流程写入本地配置，再向覆盖层广播完整 `VisualSettings`。

不改变 `AppSettings.version`、默认方案和任何字段。已有配置只包含旧枚举值，仍能原样反序列化；新配置在升级后的前后端之间正常往返。

本次不改变未知枚举值或损坏配置的既有恢复机制。若前后端枚举不同步，现有更新调用会报错并由设置页展示；自动化测试通过同时验证两端标识来防止这种发布错误。

## 测试策略

实现遵循测试驱动顺序：

1. 扩展 `Crosshair.test.tsx` 的参数化用例到七种方案，并添加四臂、中心菱形以及空心／实心结构断言；先确认测试因新类型或新结构缺失而失败。
2. 扩展 `SettingsApp.test.tsx`，验证四个新按钮、选中保存行为、菱形方案启用中心间距，以及“中心标记颜色”文案；先确认失败。
3. 在 Rust 配置测试中验证四个新枚举的 kebab-case 序列化与反序列化；先确认失败。
4. 写最小实现使以上测试通过，再清理重复渲染逻辑。
5. 运行 `pnpm test`、`pnpm build` 和 `cargo test --manifest-path src-tauri/Cargo.toml`。
6. 在设置页预览中逐项检查七个方案，并确认新方案在不同颜色、最小／最大尺寸、线宽和间距下仍可辨认。

## 验收标准

- 设置页显示七种可选方案，原三种仍可正常选择和显示。
- 四种新增方案与参考图的空心／实心菱形、臂长、臂厚和尖端方向差异一致。
- 四种新增方案使用可调主色和中心标记色，不固定参考图颜色。
- 新方案在设置页预览与实际覆盖层中使用同一组件，选择后自动保存并在重启后恢复。
- 旧配置无需迁移即可继续使用，默认仍为缺口十字。
- 前端测试、前端构建和 Rust 测试全部通过。
